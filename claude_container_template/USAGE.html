Claude DevContainer テンプレート

Claude Code と Antigravity CLI を、ホストを汚さない Docker コンテナの中で走らせるための 雛形。zellij・yazi・MCP サーバー・各種 CLI 認証をひとまとめにし、claude シェル関数から一発で起動する。

前提 — Docker（Desktop 等）が動く環境／Windows ホスト＋PowerShell プロファイルに claude 関数（windows/settings/Set-Aliases.ps1 が生成）。 VS Code の "Reopen in Container" でも起動可。
ホスト（Windows / PowerShell）で実行 コンテナ内（bash / zellij）で実行

コンテナに入っているもの

ベースは node:22-slim。Dockerfile がビルド時に以下を組み込む。

zellij
ターミナルマルチプレクサ（0.41.2）。起動時に claude / agy の 2 タブが立ち上がる
claude-env
ローカル npm パッケージ。yazi ファイラ（Ctrl+f で開閉）＋ zjstatus ステータスバー＋ Claude Code の統計 hook
claude
Claude Code 本体。native binary まで導入済み
agy
Antigravity CLI
MCP
.mcp.json をマウント。filesystem / memory / sequential-thinking / fetch / git（fetch・git は uvx）
bws
Bitwarden Secrets Manager CLI（2.1.0）。API キー配布用
gws
Google Workspace CLI
nlm
notebooklm-mcp-cli（uv tool）
gcloud
Google Cloud SDK

セットアップ（新プロジェクトに導入する）

テンプレートを自分のプロジェクトへコピーして使う場合の手順。

  1. .devcontainer/ をコピー

    このディレクトリ一式を対象プロジェクト直下へ置く。.mcp.json はプロジェクトルートに用意する。

  2. コンテナ名をディレクトリ名に合わせる

    claude 関数はカレントディレクトリ名をコンテナ名として docker exec する。 docker-compose.yml の name: と container_name: を プロジェクトのフォルダ名に書き換える（テンプレートでは両方 claude_container_template）。

  3. （gws を使うなら）ホスト側の資格情報を用意

    %USERPROFILE%\.config\gws\client_secret.json を置いておく。 docker-compose.yml がこれを read-only でマウントする。

  4. 起動する

    host · powershell 
    # プロジェクトディレクトリで
claude              # up -d してから zellij にアタッチ
claude -Rebuild     # Dockerfile 変更後（up --build -d）

    VS Code なら「Reopen in Container」でも可。postStartCommand が zellij。

  5. 必要な CLI を認証する

    使うものだけでよい。詳細は下の「認証ブリッジ」を参照。

    container · bash 
    .devcontainer/bws-login.sh <access-token>   # Bitwarden Secrets Manager
    host · powershell 
    .devcontainer\gws-login.ps1                  # Google Workspace
.devcontainer\nlm-login.ps1                  # NotebookLM

  6. 取り込む API キーを宣言する

    .devcontainer/secrets.list に環境変数名を 1 行 1 つ書く（値は書かない）。 よく使う API キー名の候補がコメントで入っているので、使う行の # を外すだけでよい。 bws-login 実行時に load-secrets.sh が走り、 ホスト env → bws の順に解決して ~/.secrets（600）へ。以降シェル起動時に自動読込。

日常の使い方

host · powershell 
claude            # 起動中ならそのままアタッチ、停止中なら up -d
claude -Rebuild   # イメージを作り直して起動
claude -AsHost    # コンテナを使わずホストの claude を実行
claude -Sbx       # devcontainer ではなく sbx サンドボックスで実行

zellij に入ったあとの操作:

  • claude タブ — claude --permission-mode auto が起動済み
  • agy タブ — agy --mode=accept-edits が起動済み
  • Ctrl+f — yazi ファイラのフローティングペインを開閉
  • Ctrl+o → d — デタッチ（コンテナは動いたまま）。claude で再アタッチ
  • 新しいペインを開くと ~/.secrets の API キーは環境変数として読込済み

認証ブリッジ

コンテナには GUI ブラウザが無いため、ブラウザ認証が要るものはホストで済ませて結果だけ渡す。 bws はトークン文字列だけで動くのでコンテナ内で完結する。

bws-login

Bitwarden Secrets Manager のアクセストークン

マシンアカウントのトークンを ~/.config/bws/access-token（600）に保存し、 ログインシェルで BWS_ACCESS_TOKEN を自動 export。続けて load-secrets.sh を実行。

container · bash 
.devcontainer/bws-login.sh <token>   # 引数・環境変数・対話入力のいずれか
host · powershell 
.devcontainer\bws-login.ps1          # -Token / 環境変数 / ホストのファイル / プロンプト
保存先
~/.config/bws/access-token（コンテナ内）
永続化
docker-compose.yml のコメントアウトされた access-token マウントを有効化すると再ビルドでも保持
注意
対象プロジェクトの全シークレット読取権を持つ。dev 限定・コミット禁止・漏洩時はローテート

secrets.list + load-secrets.sh

API キーを環境変数として取り込む

許可リストに載せた名前だけを解決する。ホスト env（docker-compose.yml の environment: 経由）にあればそれを優先し、無ければ bws のシークレット （key == その名前）から取得。結果は ~/.secrets へ。

container · bash 
bash .devcontainer/load-secrets.sh          # 再取得したいとき（bws-login でも自動実行）
BWS_PROJECT=my-proj bash .devcontainer/load-secrets.sh
リスト
.devcontainer/secrets.list — 1 行 1 変数名、# コメント可。よく使うキーの候補入り
ホスト側
ホストから渡したい変数は environment: にも名前を追加する
保存先
~/.secrets（600）／ /etc/profile.d/secrets.sh がシェル起動時に source
安全側
bws を参照できない（トークン無し／認証失敗）ときは既存の ~/.secrets を上書きしない

gws-login.ps1

Google Workspace CLI の OAuth

ホストで gws auth login（ブラウザ OAuth）を実行し、gws auth export の 資格情報をコンテナの ~/.config/gws/credentials.json へ docker cp で流し込む。

host · powershell 
.devcontainer\gws-login.ps1
.devcontainer\gws-login.ps1 -Force   # 別アカウントで上書き
前提
ホストに gws CLI ／ %USERPROFILE%\.config\gws\client_secret.json
保存先
~/.config/gws/credentials.json（コンテナ内、600）

nlm-login.ps1

NotebookLM（Chrome CDP 経由）

専用プロファイルのホスト Chrome を CDP モードで起動し、コンテナ内の cdp-proxy.js + nlm login --cdp-url でログインを操作する。普段使いの Chrome には触れない。

host · powershell 
.devcontainer\nlm-login.ps1
.devcontainer\nlm-login.ps1 -Force
手動版
ホストで .devcontainer\host-chrome-debug.ps1 → コンテナで .devcontainer/nlm-login.sh
プロファイル
%LOCALAPPDATA%\nlm-chrome-profile-<コンテナ名>（次回以降は再ログイン不要）

つまずいたら

症状対処
コンテナが起動しないdocker compose -f .devcontainer/docker-compose.yml logs node
claude が別のものを起動するフォルダ名と container_name の不一致。両方を揃える
Dockerfile の変更が反映されないclaude -Rebuild
API キーがシェルに無いsource ~/.secrets ／ bws-login 未実行 ／ secrets.list が空
bws の値を更新したいbash .devcontainer/load-secrets.sh を再実行
nlm-login が CDP に繋がらないホストで .devcontainer\host-chrome-debug.ps1 を先に実行
