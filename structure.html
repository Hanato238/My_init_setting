エントリースクリプト詳細

🖥️ windows/Start-Setup.ps1
対象: Windows 11（管理者 PowerShell）
  • installer/Install-Apps.ps1 — winget / choco / npm / uv / cargo パッケージ一括インストール。-Clinic フラグで診療所プロファイルに切替
  • installer/Install-Office.ps1 — -IncludeOffice 指定時のみ実行
  • installer/Initialize-Security.ps1 — -SyncSecrets 指定時に Bitwarden から秘密情報を配布
  • installer/Setup-Wsl.ps1 — WSL ディストリビューションのインストール
  • settings/Set-Aliases.ps1 — PowerShell プロファイルにエイリアス登録
  • settings/Set-McpServers.ps1 — shared/mcp.d/ を読んで Claude / Gemini に登録
  • settings/Set-WindowsSettings.ps1 — Explorer / タスクバー等の設定
  • settings/Set-Workspace.ps1 — ワークスペースフォルダ作成 / マウント

⚠️ 手動: Bitwarden アクセストークン（実行時に対話入力）、Windows Sandbox での事前検証

🐧 ubuntu/wsl-setup/setup.sh
対象: WSL Ubuntu（カテゴリ指定で部分実行可）
  • install_apps.sh — apt パッケージ + CLI ツール
  • initialize_security.sh — Bitwarden / ~/.secrets 設定
  • set_aliases.sh — ~/.bash_profile にエイリアス登録
  • set_mcp_servers.sh — shared/mcp.d/ を読んで Claude / Gemini に登録
  • set_workspace.sh — ~/workspace 作成・シンボリックリンク
  • set_gui.sh — ネイティブ Ubuntu のみ（WSL では自動スキップ）
  • mount_workspace.sh — Windows 側の Set-WslWorkspaceMount.ps1 から呼ばれる

⚠️ 手動: Bitwarden アクセストークン

📱 android/termux/setup.sh
対象: Android Termux → proot-distro Ubuntu
  • Termux ホスト検出時: installer/install_proot_ubuntu.sh を実行して Ubuntu を展開し終了
  • Ubuntu/proot 環境内では:
    • installer/install_llm_cli.sh — Antigravity CLI (agy) インストール
    • installer/initialize_security.sh — Bitwarden 設定
    • settings/set_workspace.sh / set_aliases.sh
    • settings/set_mcp_servers.sh

⚠️ 手動: proot Ubuntu 内で再実行が必要、Bitwarden アクセストークン

☁️ ubuntu/remote-dev/Create-Vm.ps1
対象: GCP VM — Tailscale + Orca headless server
  • config/vm-config.json を読んで gcloud compute instances create を実行
  • VM 起動時に startup-script.sh → setup.sh が自動実行
  • setup.sh が行うこと:
    • Tailscale インストール・有効化（exit node として広告）
    • Orca headless server（AppImage + systemd service）
    • Node / Docker / gh / Claude Code / agy
    • ログイン時エイリアス (orca / claude / enable-tailnet-port)

⚠️ 手動: -TailscaleAuthKey 未指定時は Tailscale 認証が手動、Tailscale 管理コンソールで exit node 承認、Orca クライアントのペアリング

☁️ ubuntu/remote-agy/Create-Vm.ps1
対象: GCP VM — Antigravity CLI (agy) 特化
  • remote-dev と同じ VM 作成パターン（config/vm-config.json + startup-script）
  • setup.sh が行うこと:
    • Tailscale インストール（exit node）
    • Antigravity CLI (agy) / uv / gcloud CLI / gws
    • NotebookLM MCP CLI
  • Orca・Docker は含まない（agy での agentic 作業に特化）

⚠️ 手動: Tailscale 認証、exit node 承認、GCP 認証 (gcloud auth login)

☁️ ubuntu/life-os/Create-Vm.ps1
対象: GCP VM — life-os 運用・push 専用
  • remote-dev と同じ VM 作成パターン
  • setup.sh が行うこと:
    • Tailscale SSH + exit node
    • 対象リポジトリのクローン（初回 SSH ログイン時）
    • サービス・Docker・GUI なし（最小構成）
  • 人間が Tailscale SSH でログインして手動 push する用途

⚠️ 手動: Tailscale 認証、exit node 承認、GitHub 認証

🤖 ubuntu/nanoclaw/setup.sh
対象: NanoClaw（Ubuntu / WSL）
  • Node.js (nvm / v24) + pnpm インストール
  • Claude Code CLI インストール
  • ~/workspace/nanoclaw にリポジトリをクローン
  • nanoclaw.sh を実行（API キー設定 + チャンネルペアリング）
  • WSL2 の場合: /etc/hosts に Telegram API IP を追加

⚠️ 手動: Anthropic API キー入力、Telegram チャンネルペアリング

🐳 claude_container_template / packages/claude-env
対象: Claude Code Dev Container（プロジェクト単位）
  • .devcontainer/devcontainer.json + docker-compose.yml + Dockerfile をプロジェクトにコピーして使う
  • API キーは docker-compose.yml の environment: に名前を書いてホストの環境変数から渡す
  • ホストの Orca から SSH で接続できる（sshd は claude-base 入り。ポートは llm が 127.0.0.1 に割り当て、~/.ssh/config に書く）
  • shared/mcp.d/ を読んで Claude / Gemini に MCP を登録
  • packages/claude-env — npx claude-env で zellij / yazi / claude-settings を一括セットアップするスタンドアロン版

⚠️ 手動: docker-compose.yml の environment: のカスタマイズ、Orca への SSH target 追加

横断レイヤー（shared / packages）

shared/mcp.d/*.json
MCPサーバー設定の分割ファイル群。カテゴリごとに分割（ai / browser / cloud / core / commerce / google / productivity）し、各 OS の MCP 登録スクリプトが統合して Claude・Gemini に適用する。
▸ Windows: Set-McpServers.ps1 ▸ WSL: set_mcp_servers.sh ▸ Termux: set_mcp_servers.sh
packages/claude-env
Claude Code 環境のスタンドアロン NPM パッケージ。npx claude-env で実行すると zellij レイアウト・yazi テーマ・claude-settings を一括展開。Dev Container 不要で使える。
▸ 任意の Ubuntu / WSL 環境
shared/skills/
Claude Code スキル定義（grill-me / grill-with-docs / notebooklm-pdf-workflow）。各プロジェクトの .claude/skills/ に配布して使う。
▸ 全プロジェクト共通
TAILNET-PORTS.md
Tailscale 経由で特定ポートを公開するヘルパーの手順書。Windows（PowerShell）・Ubuntu（ufw）の両方をカバー。
▸ remote-dev ▸ remote-agy ▸ life-os

設計方針（v1 完成条件）

冪等性

同じ入力（リポジトリ + 手動入力値）に対し、どの環境で・何度実行しても同じ環境を出力する。既存設定を二重登録しない。

秘密情報管理

Bitwarden Secrets Manager を唯一の正とする。アクセストークンは実行時の環境変数か対話入力のみ。ファイル・恒久環境変数・SecretStore への平文保存は行わない。

手動工程の明示

秘密情報の入力・外部コンソールでの承認など、自動化できない手順は README と各カードの ⚠️ 欄に明記。それ以外は空の環境で1回の実行で完結する。

場所非依存性

どの端末・VMからでも同じ環境で作業を開始できる。作業場所に仕事が拘束されない長期目標の技術基盤。
